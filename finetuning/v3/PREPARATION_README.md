## 数据来源和构造

源数据是项目已有的 `data/courses.json`，完整快照有 2,659 条记录。本轮选择 COMP、DSAI、AMA 三个部门的 354 门课程：训练集来源课程 276 门、验证集 36 门、测试集 42 门。

先按课程分组再划分集合，避免同一课程的不同提问分别进入训练与测试。同名课程、相同描述，以及高相似文本会被归为同组；例如 COMP4432 与 DSAI4203 同组，COMP2013 与 DSAI2201 同组。分组是词面启发式，不能保证消除所有语义近重复。不同集合仍共享问题模板，因此测试的是对未见课程资料的泛化，而不是对全新任务表达的全面泛化。先修课程编号作为来源资料的引用可跨集合；完整课程记录和监督目标按组隔离。

每条样本是 ChatML 的 `messages`，包含 system、user、assistant。user 中提供课程资料，assistant 为模型应该输出的 JSON。训练目标是**依据资料完成领域任务并遵循回复规则**，不是让模型脱离资料背诵整个课程库。

主要任务：课程介绍、具体学习收获、先修条件说明、开课信息缺失、资格信息不足、兴趣推荐、继续推荐、课程比较、未知课程、无检索结果、拒绝编造评价与保证资格、没有更多课程。

全部样本由本地模板与课程摘录构建；没有调用付费教师模型。6 门核心课程另有 AI 辅助通俗改写，涉及 22 条包含这些课程的样本，仍未标为人工批准。其他课程的语言与学习目标清单可能偏大纲式，**不能因为 JSON 合法就视为高质量答案**。当前训练集主要由单课程任务组成，推荐和继续推荐样本偏少，建议复核时补充真实问法并调整任务均衡。

随机示例评分不会作为训练目标，也不会被当成真实学生评价。资料未提供真实评分或开课学期时，样本明确回答不能确认。先修条件的“或／以及／排除”逻辑需要逐条核对，不将必要条件改成“非必要”。

## 审核什么

先打开 `v3/REVIEW_PREVIEW.md` 看样式，再用 `index.json` 定位具体行，对照课程原文检查：

1. 课程事实、教学方式和先修关系是否有来源支持；不能把课程库快照当成已核实的最新官方要求。
2. 简介是否通俗、在 500 字符以内；学习收获是否具体且没有夸大。
3. 推荐是否相关、每轮最多 3 门、总结与卡片一致；更多课程必须存在于提供的资料中。
4. 资料不足是否说明未知；不虚构课程、评价、学期、选课资格或真实学生背景。
5. 继续推荐是否延续学习方向，且没有重复之前的课程。

认可的样本在 `review.json` 中把 `status` 改为 `approved`，填写真实审核人和具体 `notes`。有问题的标记 `rejected` 并说明原因。不能为凑数量批量宣称已经审核。

如果需改写答案，应修改生成规则或核心课程改写文件，生成新的版本后重新检查；不要直接编辑 JSONL 后沿用旧哈希的批准记录。发布工具会拒绝内容变更后仍使用旧批准的样本。

## 本地工具

从含有 `package.json` 的项目目录运行：

```powershell
# 检查当前版本，不调用云服务
npm run finetune:validate

# 生成新的版本，已有目录不会覆盖
npm run finetune:prepare -- finetuning/v4

# 仅导出已批准的训练集与验证集；没有批准数据时会明确拒绝
npm run finetune:export

# 评测演练，默认不发请求、不产生调用费用
npm run finetune:evaluate -- --model qwen3-8b --limit 10
```

只有显式添加 `--run` 才会实际调用评测模型。付费调用和数据上传应先确认预算与账号条件。训练启动脚本没有创建，也没有执行云端上传或训练命令。

`finetune:export` 从不导出 test 文件用于训练。审核前的 draft 文件只是构造结果，不能当成已批准的训练发布包。

token 估算工具使用公开的 Qwen3-8B tokenizer，仅下载分词文件，不下载模型权重、不上传课程数据。依赖隔离在 `.venv-finetuning` 中：

```powershell
.\.venv-finetuning\Scripts\python.exe scripts/estimate-finetuning-tokens.py
```

复制项目时无需复制虚拟环境或 tokenizer 缓存；如需重算，可新建本地 Python 环境并安装 `tokenizers`。JS 数据生成、检查、导出和评测演练只需项目原有 Node 依赖。

## 拟用的百炼训练方案与费用

候选模型为北京地域的 **Qwen3-8B / qwen3-8b**，训练方式 SFT，采用高效训练（LoRA）；先考虑 1 轮小规模实验，其他超参数以控制台支持和默认建议为准。最终以账号实际可选模型、权限、报价为准，当前的普通 `qwen-plus` API 接入不代表已经具备训练或部署权限。

按 2026-11-03 查到的官方 Qwen3-8B 训练单价 ¥0.006/千 token，本地通用 ChatML 分词估算：训练草稿约 2,248,369 token，1 轮约 ¥13.49，3 轮约 ¥40.47。最长样本约 5,567 token；控制台需选择能容纳完整样本的序列长度，避免默默截断先修关系等内容。

这些是**全部草稿**的初步估算，未按最终批准样本重算，也不是云平台最终报价；不含部署、模型调用、可能的验证费用等。获批后再核对控制台的计数、预计金额、部署方式和停止规则。没有批准预算、没有启动训练。

## 如何公平展示微调效果

应比较同一基础模型 **qwen3-8b 微调前**和其**微调后版本**，使用相同问题、课程上下文、提示词和推理设置。现有 qwen-plus 可作为额外业务参照，不能把两种不同基础模型的差异全部归因于微调。

`finetune:evaluate` 直接检查模型原始回复，不使用服务器的格式修正，以免“后端强制最多 3 门”掩盖模型本身是否学会规则。可记录 JSON 通过率、课程数量、编号是否出自上下文、总结与卡片是否一致、简介长度、继续推荐是否重复、用量和耗时。脚本仅检查结构与编号来源，**不是全文事实准确率**；相关性、易懂程度和先修关系的正确解释仍需独立评阅。

正式训练后另存任务 ID、基础模型、数据版本及哈希、超参数、训练／验证曲线、用时、费用、部署模型 ID和前后对比结果。本目录没有虚构这些结果。
